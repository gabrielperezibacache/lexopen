# Optional Altazor desktop gateway

Official contract read at commit `6aee950bdf971ff41f3867763a0ec9f5ef8ef8e3`:

- [HTTP API](https://github.com/madkoding/kitties/blob/6aee950bdf971ff41f3867763a0ec9f5ef8ef8e3/docs/API.md)
- [Gateway handlers](https://github.com/madkoding/kitties/blob/6aee950bdf971ff41f3867763a0ec9f5ef8ef8e3/internal/gateway/gateway.go)
- [Desktop lifecycle](https://github.com/madkoding/kitties/blob/6aee950bdf971ff41f3867763a0ec9f5ef8ef8e3/internal/kitty/kitty.go)
- [Attachment validation](https://github.com/madkoding/kitties/blob/6aee950bdf971ff41f3867763a0ec9f5ef8ef8e3/internal/attach/attach.go)

Disabled unless `ALTAZOR_COMPUTER_ENABLED=1`. Configuring a gateway also requires the Host's explicit loopback listener (`LEXOPEN_BIND` or `HOSTNAME` set to `127.0.0.1`/`::1`), a same-origin local browser session and CSRF validation. A remote browser cannot configure a service on the Host's loopback. Remote gateway/TLS support is intentionally unavailable.

The operator must provision a separate gateway and data directory for each owner/scope. This is a deployment requirement, not a tenant-isolation feature supplied by the gateway. Endpoint reservations are unique and retained. The broker rejects an instance that contains unknown desktops. The broker never reads a global artifact/skill/vault library. It cannot establish that an operator's pre-existing data directory has no historical content; a fresh dedicated directory is required. Do not reuse a gateway for another professional or case.

Model credentials are configured separately in the desktop gateway. Existing LexOpen mail/Google/LinkedIn/Codex credentials, session cookies and document stores are not copied into it. New desktop connectors have their own explicit configuration. Secretos can send a chosen credential to the held desktop keyboard after a one-use confirmation; it never puts that value in model input or a readable API. A gateway bearer token is encrypted at rest with owner/workspace/scope binding and never returned by an API. Requests use fixed endpoints; there is no raw proxy, shell/exec, library or global-artifact route.

The firm's `local_only` policy blocks session creation, tasks and manual input/control. A loopback gateway address does not establish that its model is local, and the current official provider contract cannot attest its actual destination. Reading, cancellation and stopping remain available for existing sessions. The policy is checked again at action claim and immediately before sending tasks. Changing gateway credentials/provider or disabling it requires closing active or uncertain sessions first.

The gateway runs desktops in containers. Empty `connectors` means **all** connectors: the broker sends `['-']` for none or a bounded explicit list persisted with the session. With connectors, it requires the pinned LexOpen permission patch, creates the kitty without starting it, installs per-connector `* / ask` rules, then starts it. The patch blocks model changes to rules and requires a fresh approval for connector calls even with learned trust or `auto` rules. Decisions are bound to owner, workspace, kitty, chat and selected connector, with `always:false` and no automatic resend. This controls connector calls, not every interaction a model might perform in the browser. The professional separately submits each task and its selected files and can take manual control, cancel or stop the desktop.

See [Conexiones y Secretos](../../../../docs/ALTAZOR-CONEXIONES.md) for the 48-adapter catalog, OAuth application prerequisites, platform restrictions and exact patch/build commands. The generic Host program adapter remains blocked. Desktop connector settings are stored by the upstream runtime under its own file permissions; they do not inherit Secretos encryption.

Secretos grants last at most 60 seconds and bind owner, secret revision, session configuration, updated control state and declared HTTPS origin/field. Redemption claims once before network activity, serializes typing with control/input/rotation, sends through the pinned stdin keyboard implementation and leaves hold enabled without Enter. Origin/field are human declarations, not DOM attestations. A site or visible field can expose a value after control returns to the model. Mobile screenshots support fit, 100% and 150% zoom with scrolling; pointer coordinates map to the original remote pixels.

Selected uploads are limited locally to five files/20 MiB total (5 MiB per image). Actual pinned source accepts 20 files/100 MiB, while API.md still says six/20 MiB; the stricter broker limit avoids that discrepancy. The gateway independently validates the actual files.

New desktops have no access deadline (`expiresAt = NULL`). The broker explicitly sets and verifies the owned Kitty's `auto_off_minutes: 0`; the pinned container runtime already uses `--restart unless-stopped` and an owner-scoped workspace bind. Closing the browser does not close the desktop. An explicit stop retains the container and chat; resume checks current owner, case, workspace, model policy, selected connectors and conflicting desktops before starting that exact Kitty. It never creates a replacement or replays model work. Legacy dated sessions retain their previous deadlines until their owner explicitly adopts them as persistent. A closed legacy desktop may also be resumed after current authorization checks. Unconfirmed tasks block resumption pending review. Credential grants and manual-control leases still expire independently, and task budgets remain bounded. Receipts contain owner/session-bound HMACs and bounded metadata, never typed inputs or upload bytes.

`computer.test.ts` exercises synthetic contract fixtures, including a loopback HTTP fixture. It does not prove a real Altazor desktop, provider account or Docker/Podman runtime is operational.

## Real container check without user credentials

On a disposable Linux CI runner with Docker, check out and archive the exact commit above. Build the gateway with `make WEB=0 VERSION=lexopen-ci build`. From LexOpen, run `node scripts/altazor/build-desktop-image.mjs <archived-source>` and use the immutable image ID it reports. The recipe builds the real desktop and adds the LexOpen document tool profile. Debian and upstream build inputs require network. Tool checks run without network as the unprivileged desktop user. Use a fresh dedicated gateway home and a real, non-demo runtime. [Desktop preparation guide](../../../../docs/ESCRITORIO-ALTAZOR.md).

Run a local OpenAI-compatible HTTP fixture and provide an explicit configuration with a new temporary `data_dir` and `containers.workspace`, no pre-created desktops, no connectors, a fictitious bearer token and a provider named `fixture` pointing at that fixture. Set `containers.runtime: docker`, the locally built image, `containers.auto_update: false`, `containers.auto_off_minutes: 1`, `updates.gateway: "off"` (the quotes are required by the pinned YAML reader), and `gateway.listen: 127.0.0.1:<unused-port>`. Start `dist/kitties -config <temporary-yaml> gateway`. The gateway prints its token at startup, so do not publish raw logs, even from this credential-free fixture.

Through this broker, verify actual health/version/container availability, desktop creation, a non-empty PNG screenshot, hold/type/release, a selected fictitious upload, cancel and stop. Assert no foreign owner/case can reach any operation and no global artifact or exec endpoint is called. Stop only the gateway/container IDs created by the check and remove only its temporary directories. This proves real container and adapter behavior with a synthetic model response; it does not establish autonomous model performance or an operational personal provider account.

Primary build/config sources: [Makefile](https://github.com/madkoding/kitties/blob/6aee950bdf971ff41f3867763a0ec9f5ef8ef8e3/Makefile), [configuration example](https://github.com/madkoding/kitties/blob/6aee950bdf971ff41f3867763a0ec9f5ef8ef8e3/configs/kitties.example.yaml), [CLI entry point](https://github.com/madkoding/kitties/blob/6aee950bdf971ff41f3867763a0ec9f5ef8ef8e3/cmd/kitties/main.go).

The independent `altazor-computer-runtime` CI job implements this check using `scripts/altazor/computer-smoke.ts`, a PostgreSQL 16 service, an archived checkout without `.git`, a fixed Lumen build commit, a verified local image ID, a dedicated unprivileged gateway UID with outbound firewall rules, and an internal Docker network. It inspects actual mounts/namespaces/environment, copies back only the chosen synthetic upload from that container, and cancels an actual asynchronous screenshot task while its synthetic provider request is pending. Only the fictitious desktop PNG and a curated result summary are retained; raw gateway output is never an artifact. Running it locally fails at its explicit CI/opt-in guard. A successful remote job is required before calling the real-runtime smoke verified.
